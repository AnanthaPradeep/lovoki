# Sample content

**Sample content is fake, development-only data.** It exists so Discover, the Feed and profiles look lived-in while LOVOKI has almost no real members. It is always labelled, it can never reach a real person, and it must never exist in production.

## What is sample

| Thing | Detail |
|---|---|
| **30 sample adults** | Fictional names, 21 public and 9 private accounts, mixed genders and interests, ages 21 to 45, varied intentions, bios with line breaks and emoji, prompts, interests, optional details with mixed per-field visibility, 3 to 6 photos each, a city each across Tamil Nadu, Kerala, Karnataka, Maharashtra, Delhi, London, Berlin, Toronto, Singapore and Sydney. About 80% are discoverable in Discover. |
| **About 230 posts** | Public accounts have 6 to 12 each, private ones 5 to 7. Captions are short, medium, long (up to 1,400 characters) or emoji; about one in ten is text-only; audiences are public or followers; timestamps are spread over the last 60 days. Private accounts' posts are hidden from strangers, so the lock state is testable. |
| **Follow graph, likes, saves, comments** | Samples follow each other (some requests to private samples stay pending). Counts shown anywhere are derived from these rows; nothing is inflated. |
| **Pictures** | Original (1080 wide), a 400 px thumbnail and a blurhash for every post picture; avatar and blurhash for every person. |

Every sample profile, post and comment carries `is_sample = true` (posts and comments inherit it from their author in the database, so a client cannot set or clear it). The UI shows a **Sample** badge on people, posts, search results, suggestions and Discover cards.

## What a sample can and cannot do

- **Cannot log in**: the address ends in `@sample.lovoki.invalid` (a reserved name that can never receive mail), the password is random and thrown away, and the account is permanently banned.
- **Cannot match**: a dating like on a sample stores nothing and never produces a match. The Discover card says so in words.
- **Cannot be messaged**: there is no chat yet, and Phase 5 must refuse sample accounts (`_is_sample()` exists for that).
- **Receives no notifications**: nothing is delivered to a sample.
- **Cannot be reported**: a report is refused with "This is sample content, so there is nobody to report." (only after the normal visibility check, so it cannot be used to discover which hidden ids are samples).
- **Never accepts a follow request.** Following a public sample is instant; a request to a private sample stays pending forever, and the profile says so.
- **Cannot exist in production**: a trigger raises an error when `is_sample` is set while `app_config.environment` is `production`; `app_config` can only be changed by a migration.

## Images and licences

No photographs of people, no real-person photos, no AI-generated faces.

- **Post and "photo" pictures** are generated by `scripts/lib/sample-art.mjs` with eight different compositions (horizon, circles, waves, mountains, arches, dots, grid, stripes) from a seeded palette. Same seed, same picture.
- **Avatars** are illustrations from three DiceBear styles. I read each package's `LICENSE` file myself (`node_modules/@dicebear/<style>/LICENSE`). The *design* (artwork) licence is separate from the MIT licence of the code, and for all three it is **CC0 1.0**:

## How to use it

```sh
npx supabase status -o env > scripts/.seed.env     # local keys; git-ignored
node scripts/seed-sample-content.mjs               # prints what it will create, then asks you to type "seed"
node scripts/seed-sample-content.mjs --yes         # local only: skip the question
node scripts/seed-sample-content.mjs --users 12    # fewer people
node scripts/seed-sample-content.mjs --remove      # delete every sample account, post, comment and stored file
```

It is **deterministic** (same inputs, same rows) and **idempotent**: a second run changes nothing, which an integration test proves by comparing every row and the number of stored files.

To see what a real account sees, turn on "Hide sample content" in Settings. That switch exists only when the app is started with `VITE_SHOW_DEV_TOOLS=true`.

## Hosted (only with your explicit approval)

The seeder refuses to write to anything but your local stack unless you pass **both** `--hosted --confirm-ref <your 20 character project ref>`, have a git-ignored `scripts/.seed.hosted.env` containing `SEED_URL=https://<ref>.supabase.co` and `SEED_SERVICE_KEY=...`, the URL matches the ref you typed, the project's `app_config.environment` is `development`, **and you type the ref again** when asked. It prints what it will create first. There is no `--yes` for hosted. The service key lives only in that untracked file: never in a tracked file, a `VITE_` variable, a log or chat.

I have not run it against your hosted project and will not without that approval.

## Never in production

`node scripts/assert-no-sample-data.mjs --expect production` exits **1** if any sample profile, post or comment exists, and exits **2** if it cannot check (a missing setting is a failure, never a pass). Phase 6 (release prep) must run it against the production project before every release, and must set `app_config.environment` to `production` by migration. If it fails: `node scripts/seed-sample-content.mjs --remove`.
